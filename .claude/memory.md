# CJP-CLI-DEV 项目记忆库 (Context Memory)

> 本文档用于记录项目开发过程中形成的重要上下文，提供给未来对话中的 AI 助手或新加入开发的成员作为重要参考。包含项目决策记录、用户偏好、已知 Bug 与临时解决方案等核心背景知识。

## 一、 用户协作与偏好 (User Preferences)

1. **防御性编程思维 (Defensive Programming)**
   - 在处理高风险操作（如`--fix`自动修复、清理缓存、调用外部系统命令）时，必须充分做到边界测试和异常捕获。发生不可逆修改前需要询问用户；如果检查修复不通过提示或者执行过程中出现错误，必须保证不对用户原有功能造成影响；跨平台异常需要通过 try-catch 拦截并给予友好提示（避免裸出错崩溃退出）。
2. **高度重视架构和规范设计**
   - 对项目文档的结构化设计要求极高。喜爱以“规格书 (Specs)”、“文档手册”、“从零构建记录”及“情景模拟面试 (Interview Q&A)”等视角对代码的设计进行完善。每次大型修改后，都要求主动将改动同步到设计架构文档中。
3. **保留业务流注释 (Preserve Comments)**
   - 本项目中文注释覆盖率非常完整。在重构、封装和重构既有文件时，必须严格保留代码原有的核心代码块逻辑注释，避免由于简化影响源码在日后的阅读。

## 二、 核心架构与决策记录 (Decisions)

1. **Lerna 版本锁定与依赖控制**
   - **决策记录**：项目曾尝试升级到 Lerna 8.x 但存在执行兼容问题，所以降级并锁定在 Lerna `6.6.2` 版本，采用 Fixed 版本模式统一发版。
   - **缺陷替代**：针对 `lerna bootstrap` 在 Windows 环境软链常常失败的问题，项目不依赖原有命令，独立编写了 `scripts/install-deps.js` 一键批量 `npm install` 并在最后给执行模块执行 `npm link` 从而实现平顺的软链接测试流程。
2. **命令动态加载架构**
   - **决策记录**：核心执行进程（`exec`）没有使用静态的 `require()`。它使用一个映射表，通过 `npminstall` 将命令子包下载到系统的本地缓存并更新，并统一使用 `node -e "require('...').call(xxx)"` 生成隔离的**子进程**来运行代码。好处是支持独立的命令升级更新、提供防崩溃主进程的强隔离、且能利用 `--targetPath` 本地无缝热重载调试。
3. **网络与更新检测异步化**
   - **决策记录**：命令全局包更新探测（`checkGlobalUpdate`）最初是强阻塞运行，遭遇无网或者 NPM 超时环境会使 CLI 拒绝工作。后将其修改为不加 await 并在请求尾部加入 `.catch(() => {})` 进行静默抑制，同时对 `axios` 扩展了 30s 默认超时防御。

## 三、 跨平台踩坑与兼容性 (Bugs & Workarounds)

1. **Windows 系统级原生命令缺失判定策略**
   - **已知缺陷**：如 `ssh-keygen`、`ssh -T`、`scp` 等常用环境探测命令在 Windows 上大多非系统原生自带内置工具（除非独立安装 Git for Windows 并在环境变量勾选）。原本使用 Node 的 `cp.execSync()` 在缺失该命令的 Windows 系统上报错，导致应用闪退。
   - **实践方案**：执行原生命令之前统一编写 `try...catch` 捕捉块，在错误信息里专门嗅探捕捉 `e.code === "ENOENT"` 或 `e.message.includes("ENOENT")`，一旦捕获就拦截错误并进行中文步骤提示要求用户安装相关组件环境（注意由于 `ssh-keygen --help` 这条命令在退出时往往是 Exit Code 1，需明确只排除 ENOENT，不以非零退出代码来判定找不到命令）。
2. **终端换行符 (Line endings in stdout)**
   - **已知缺陷**：调用子进程处理 Git 客户端原始命令行输出（如 `git status`、`git ls-remote` 获取 tag）时，由于 Windows 下通常为 `\r\n`，macOS为 `\n`。如果利用 `split("\n")` 直接处理会有遗留字符。
   - **实践方案**：所有从终端获取输出的字符串处理分割统一使用 `split(/\r?\n/)`。
3. **路径符号容错统一 (format-path)**
   - **已知缺陷**：Node.js 环境中的相对/绝对路径中的反斜杠常常在 Windows 环境跟 Unix 对标不同步。
   - **实践方案**：所有动态 `rootFilePath` 或涉及到动态 `require()` 的跨文件操作，都在核心层统一交给了脚手架内置的 `@cjp-cli-dev/format-path`（将 `\` 转置为 `/`）确保跨端正常识别。
